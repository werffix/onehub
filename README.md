# one//hub

Закрытая база знаний с входом по персональному ключу. Фронтенд переведён на Vite, React и TypeScript; навигация работает через React Router, загрузка данных — через TanStack Query. Редактор статей использует TipTap/ProseMirror. Существующий Node.js backend и JSON-хранилище оставлены, чтобы сохранить действующую авторизацию, пользователей, ключи, устройства и сессии без миграции базы данных.

## Возможности

- `/` — каталог непустых категорий, поиск по всей базе.
- `/category/:slug` — список опубликованных статей категории, поиск внутри неё.
- `/article/:slug` — чтение статьи с широкой колонкой, датой обновления, прогрессом и копированием ссылки. Скрытая из каталога статья открывается по прямой ссылке только авторизованному пользователю.
- `/admin` — разделы базы знаний и пользователей; CRUD статей и категорий, публикация/снятие, поиск, фильтры, дублирование и защита удаления категории со статьями.
- `/admin/articles/new`, `/admin/articles/:id` — отдельный TipTap-редактор. Есть форматирование, ссылки, списки и чек-листы, таблицы, изображения, код с подсветкой, выбор шрифта/размера/цвета, undo/redo, предпросмотр, автосохранение в черновик и локальное восстановление.
- Светлая/тёмная тема хранится в браузере. Адаптивная шапка общая для пользовательских страниц.

## Стек и структура

- `src/` — React/TypeScript UI; `src/pages/Editor.tsx` загружается отдельным чанком.
- `server.js` — текущий HTTP backend, вход по ключу, роли, устройства, сессии, CSRF, API и раздача SPA.
- `lib/content.js` — очистка HTML по белому списку и нормализация legacy-разметки.
- `data/store.json` — существующие учетные записи и метаданные; `data/articles/<id>.html` — очищенный HTML; `data/articles/<id>.json` — TipTap JSON.
- `scripts/migrate-kb.js` — идемпотентная миграция существующего хранилища.
- `test/` — интеграционные проверки backend и миграции.
- `deploy/` — systemd и пример Caddy.

Для одного сервера и текущего объёма данных оставлен JSON backend: это позволяет использовать текущие ключи и не требует переносить credential/session схему в новую БД. Он предназначен для одного Node-процесса; при росте нагрузки следует отдельно спланировать PostgreSQL и транзакционный импорт.

## Локальный запуск

Node.js 20+:

```sh
npm ci
cp .env.example .env
```

Заполните `ADMIN_KEY` (четыре группы из четырёх разрешённых символов) и три секрета не короче 32 символов: `KEY_ENCRYPTION_SECRET`, `KEY_LOOKUP_SECRET`, `SESSION_SECRET`.

Для разработки нужны два терминала:

```sh
npm run dev:server
npm run dev
```

Vite запускается на `http://127.0.0.1:5173` и проксирует `/api` и `/uploads` на Node `127.0.0.1:3000`. Админ входит по `ADMIN_KEY`. Демо-данные добавляются только в development: `npm run seed`.

Сборка и запуск production (dev-зависимости нужны на этапе компиляции TypeScript/Vite):

```sh
npm ci --include=dev
npm run build
# Необязательно на сервере после сборки:
npm prune --omit=dev
NODE_ENV=production node server.js
```

Backend раздаёт production UI из `dist/`; без предварительной сборки он отвечает `503` на HTML-маршруты, чтобы случайно не включить прежний интерфейс. В разработке UI открывается через Vite.

## Миграция существующих данных

Сделайте резервную копию каталога данных перед первым запуском новой версии. Если приложение уже использует `/var/lib/0ne-hub`, укажите этот путь; локально по умолчанию берётся `./data`.

```sh
DATA_DIR=/var/lib/0ne-hub npm run migrate:kb
```

Скрипт сохраняет `users`, `sessions`, `devices`, `logins`, `audit`, существующие ID статей и файлы. Создаёт недостающие категории, привязывает статьи по прежнему имени категории (или `Без категории`), добавляет slug и обязательные поля, переносит HTML из `store.json` в отдельные файлы, нормализует заголовки/пустые абзацы и санитизирует HTML. Повторный запуск безопасен.

## API

Все `/api/*` кроме входа требуют сессию; изменяющие запросы требуют `x-csrf-token` из `GET /api/session`. Все admin endpoints дополнительно проверяют роль на сервере.

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/session`, `/api/login` | Проверка сессии / вход по ключу |
| POST | `/api/logout` | Выход |
| GET | `/api/categories` | Категории с количеством статей; для user скрытые и пустые исключены |
| GET | `/api/categories/:slug/articles` | Статьи категории |
| POST/PATCH/DELETE | `/api/categories[/:id]` | CRUD категории; удаление с непустыми статьями требует переноса или явного удаления |
| PUT | `/api/categories/order` | Изменение порядка категорий |
| GET | `/api/articles?q=&category=` | Поиск и список доступных статей |
| GET/POST | `/api/articles/:slug`, `/api/articles` | Чтение / создание |
| PUT/DELETE | `/api/articles/:id` | Сохранение, публикация или удаление |
| POST | `/api/articles/:id/duplicate` | Создать черновик-копию |
| POST | `/api/uploads` | Проверка изображения, ресайз, удаление EXIF, перекодирование в WebP |
| GET/POST | `/api/users` | Список / создание участника (админ) |
| GET/PATCH/DELETE | `/api/users/:id` | Управление участником (админ) |
| PATCH | `/api/devices/:id` | Управление устройством (админ) |

## Проверка

```sh
npm run build
npm test
```

Проверяются роли и доступность публикаций, санитизация XSS, защита удаления категории, CSRF, существующая работа ключей/устройств и идемпотентность миграции.

## Ограничения текущей итерации

Хранилище рассчитано на один процесс и не обеспечивает транзакции. Загрузка изображений пока проходит через JSON data URL по HTTPS, затем проверяется декодером Sharp и сохраняется с новым WebP-именем; содержимое редактора хранит только URL. Замер критерия 50 000 символов/30 изображений и ввод менее 50 мс не проводился. Редактор покрывает основные блоки, но расширенные взаимодействия с таблицами, подписи/resize изображений, slash-меню и отдельные подсказки горячих клавиш требуют следующего прохода. Подсветка использует набор грамматик Lowlight common. Автоматические UI/e2e и браузерные проверки также не проводились.
