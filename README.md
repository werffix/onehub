# 0ne//hub

Закрытый кабинет для чтения статей с доступом по персональному ключу. Интерфейс на русском языке, адаптирован для телефона, планшета и компьютера. HTML из вложения использован только как визуальный ориентир: светлая палитра, размытая боковая панель, нейтральные карточки и мягкие скругления. Тексты и контент написаны заново.

## План и стек

Порядок реализации: каркас и интерфейс → вход по ключу и роли → управление статьями и участниками → редактор → базовые меры защиты → интеграционные тесты и документация.

Выбран Node.js 20+ без обязательных npm-пакетов и без шага сборки: проект легко запустить на чистой установке Node. Сервер использует встроенные `http`, `crypto` и `fs`; данные сейчас хранятся в локальном JSON-файле. Для редактора используется небольшой встроенный редактор на `contenteditable` с базовыми командами форматирования. Для расширенного редактора в следующей версии следует перейти на TipTap: его расширяемые узлы подходят для таблиц, кода, изображений, списков задач и безопасного преобразования документа.

Выбор JSON-файла вместо SQLite сделан ради нулевой установки и простого локального старта. Это демонстрационная архитектура для одного процесса, а не замена транзакционной БД для многопользовательского публичного сервиса. Никакие тексты из визуального референса не перенесены.

## Запуск

Требуется Node.js 20 или новее.

```sh
cp .env.example .env
```

Затем задайте в `.env` собственные непохожие на примеры значения: `ADMIN_KEY` — четыре группы по четыре допустимых символа, остальные три секрета — по 32 и более случайных символа. Сервер намеренно завершится с ошибкой, если останется демонстрационный ключ или незаполненный секрет.

```sh
npm install
npm run dev
```

Откройте `http://localhost:3000`. `npm install` не скачивает пакеты, так как приложение использует только Node.js. В dev-режиме демо-данные можно добавить командой `npm run seed`; она печатает одноразовые ключи созданных демо-пользователей. Админ входит по значению `ADMIN_KEY`.

Данные и журнал создаются в `data/store.json`. Каталог исключён из Git. Путь можно переопределить переменной `DATA_DIR`. Для production задайте `NODE_ENV=production`, настройте HTTPS на reverse proxy и ограничьте доступ к каталогу данных.

## Возможности

- Вход только по ключу с маской ввода, серверными сессиями, cookie `HttpOnly` и `SameSite=Strict`.
- Роли пользователя и администратора проверяются на сервере.
- Пользователь видит только опубликованные статьи; администратор создаёт, редактирует, удаляет и публикует материалы.
- Участники создаются с криптографически случайным ключом, ключ шифруется AES-256-GCM, для поиска используется HMAC-SHA256. В карточке доступны просмотр и замена ключа.
- Устройства привязываются по отдельному случайному cookie; поддерживаются лимит, список устройств и блокировка. В карточке показаны IP и история попыток входа.
- Статьи проходят серверную очистку HTML, изменения API требуют CSRF-токен.
- Встроенный редактор поддерживает базовое форматирование, заголовки, списки, цитаты, отмену и повтор.

## Структура

- `server.js` — HTTP API, хранение, авторизация и защитные заголовки.
- `public/index.html`, `public/style.css`, `public/app.js` — приложение и адаптивный интерфейс.
- `test/app.test.js` — интеграционные проверки API.
- `SECURITY.md` — текущие меры защиты и известные пробелы.

## API

Все ответы API — JSON. Ключ передаётся только в теле `POST /api/login`.

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/session` | Без входа | Текущая сессия и CSRF-токен |
| POST | `/api/login` | Без входа | Вход по ключу |
| POST | `/api/logout`, `/api/logout-all` | Сессия | Завершить сеанс / все сеансы |
| GET | `/api/articles?q=` | Пользователь, админ | Поиск по доступным статьям |
| GET | `/api/articles/:id` | Пользователь, админ | Прочитать статью |
| POST | `/api/articles` | Админ + CSRF | Создать статью |
| PUT/DELETE | `/api/articles/:id` | Админ + CSRF | Изменить/удалить статью |
| GET/POST | `/api/users` | Админ / админ + CSRF | Список / создать участника |
| GET/PATCH/DELETE | `/api/users/:id` | Админ | Карточка / изменить / удалить участника |
| PATCH | `/api/devices/:id` | Админ + CSRF | Блокировать или вернуть устройство |

Изменяющие запросы отправляют `x-csrf-token`, полученный из `/api/session` или ответа входа. `TRUST_PROXY=true` разрешает брать IP из `X-Forwarded-For`; устанавливайте это только за доверенным reverse proxy.

## Известные ограничения

Это рабочий локальный MVP, но не завершённая production-платформа из исходного технического задания. Нет полноценного TipTap, загрузки/обработки изображений, таблиц и расширенной типографики, SEO-форм, idle-таймаута сессии, отдельного админского интерфейса выхода со всех устройств, транзакционной БД, ORM/Zod, Helmet, CSP nonce, CAPTCHA и полной схемы событий аудита. Простейшая очистка HTML не заменяет зрелую библиотеку санитизации. Rate limit хранится в памяти процесса и не координируется между инстансами. `npm audit` для этого проекта неприменим к сторонним пакетам: runtime-зависимостей нет. Для реального размещения нужно закрыть перечисленные пробелы, добавить PostgreSQL/SQLite, TipTap, строгую санитизацию и автоматические проверки загрузок.
