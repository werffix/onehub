# Безопасность 0ne//hub

## Реализованные меры

- Сервер отказывается запускаться, если `ADMIN_KEY` отсутствует, имеет неверный формат или совпадает с демонстрационным значением. Три независимых секрета обязательны и должны быть длиной не менее 32 символов.
- Ключ пользователя генерируется через `crypto.randomBytes`. В локальном хранилище лежат AES-256-GCM ciphertext и HMAC-SHA256 digest. Сравнение digest выполняется `timingSafeEqual`. Открытый ключ показывается только при создании или по запросу администратора.
- Сессия имеет случайный ID, HMAC-подпись, абсолютный срок 12 часов и серверный отзыв. Cookie `HttpOnly`, `SameSite=Strict`; флаг `Secure` включается в production.
- Устройство получает отдельный случайный HttpOnly cookie, а в данных хранится только HMAC. UA используется как подпись в интерфейсе, не как единственный идентификатор. Лимит и блокировка проверяются на сервере.
- Неудачные входы получают одинаковый ответ с фиксированной задержкой; IP после пяти попыток блокируется с прогрессивным интервалом. Успешная авторизация сбрасывает счётчик.
- Все изменяющие API-запросы требуют CSRF-токен. Пользовательская роль не может обращаться к API управления пользователями или изменять статьи. Черновики недоступны пользователю.
- Сервер очищает HTML статьи, ограничивает размер JSON тела, не раскрывает stack trace клиенту в production. Выключенный `x-powered-by` не применим к встроенному HTTP серверу.
- Отдаются CSP, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` и `Permissions-Policy`; в production включается HSTS. Закрытые HTML-страницы имеют `noindex`, `robots.txt` запрещает индексацию.
- Ключ передаётся только в теле запроса. Файл данных исключён из Git.

## Настройка и операционные меры

Сгенерируйте независимые значения секретов криптографическим генератором и храните `.env` вне репозитория. В production обслуживайте сайт только по HTTPS. Если включён `TRUST_PROXY`, proxy должен перезаписывать, а не принимать от клиента `X-Forwarded-For`. Ограничьте права на `data/`, настройте резервное копирование и проверяйте восстановление копии. Встроенный JSON store рассчитан на один процесс и не даёт транзакционных гарантий.

## Ограничения, которые нужно закрыть до публичного запуска

- Заменить JSON-файл на SQLite/PostgreSQL с транзакциями и схемной валидацией.
- Заменить собственную очистку HTML на зрелую серверную библиотеку с белым списком тегов, атрибутов и схем ссылок. Текущая регулярная очистка ограничена и не гарантирует защиту от сложных XSS payload.
- Заменить упрощённый редактор на TipTap и проверить каждое расширение, HTML преобразования и URL.
- Добавить проверку MIME и magic bytes, перекодирование изображений, лимит размера и случайное хранение файлов. Сейчас загрузка файлов отсутствует.
- Вынести rate limit и прогрессивные задержки в разделяемое хранилище; добавить idle-таймаут, CAPTCHA при необходимости и тесты гонок.
- Завершать отзыв сессии на каждом защищённом запросе и аудировать все административные действия с согласованной схемой.
- Добавить CSP nonce при появлении inline скриптов и интеграционные тесты IDOR, блокировок, ротации ключа, загрузки файла и rate limit.

`npm test` содержит начальные интеграционные проверки. Они не являются независимым аудитом безопасности.
