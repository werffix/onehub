# Безопасность one//hub

## Реализованные меры

- Вход по ключу, роли, устройства, ограничение устройств, отзыв и ротация ключей остаются на существующем Node backend. Ключи пользователей хранятся как AES-256-GCM ciphertext и HMAC-SHA256 digest; сессии подписаны HMAC и выдаются через HttpOnly/SameSite cookie.
- Все API кроме входа/проверки сессии требуют вход. Административные операции дополнительно проверяют роль на сервере. Модифицирующие запросы требуют CSRF токен.
- Валидация категории и статьи проходит через Zod; TipTap-документ рекурсивно ограничен по глубине/числу узлов, ссылки проверяются. JSON body имеет верхний лимит.
- HTML проходит серверную очистку `sanitize-html` с белым списком тегов, атрибутов, URL-схем и CSS свойств как при сохранении, так и при старте на legacy данных. HTML пользователя не считается доверенным.
- Изображение проверяется декодером Sharp по содержимому, ограничено 5 МБ, ориентируется по EXIF, уменьшается, перекодируется в WebP и сохраняется под случайным именем. EXIF не переносится. В документ редактора сохраняется URL, не base64.
- CSP не разрешает inline scripts (`script-src 'self'`), присутствуют `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`; в production включается HSTS. Закрытые страницы помечены noindex.
- Сервер требует собственный admin key и три уникальных секрета длиной от 32 символов. Файл данных исключён из Git.

## Операционные меры

В production используйте HTTPS через Caddy, храните `/etc/0ne-hub.env` с режимом `600`, ограничьте права каталога данных и регулярно проверяйте восстановление backup. `TRUST_PROXY=true` включайте только за доверенным reverse proxy, который сам выставляет forwarded-заголовки.

JSON store и rate limit в памяти рассчитаны на один Node процесс. Несколько реплик или запись несколькими процессами требуют миграции на транзакционную БД и общего rate-limit store. Не меняйте существующие encryption/lookup/session secrets: это лишит доступа к сохранённым зашифрованным ключам или сессиям.

## Оставшиеся ограничения

Интеграционные тесты покрывают базовые роли, XSS, CSRF, защиту от доступа к черновикам/скрытым категориям, удаление категории и миграцию. Нет независимого аудита безопасности, e2e-проверок браузера и стресс-бенчмарка большой статьи. Формат JSON изображения пока передаётся в API data URL, хотя на сервере преобразуется в URL-файл; для крупных загрузок стоит перейти на multipart streaming. Редакторские HTML преобразования новых расширений следует дополнительно проверять при добавлении расширений.
